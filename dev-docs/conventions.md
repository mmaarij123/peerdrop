# Coding conventions

- Edit page components and styles in `frontend/`. The build writes HTML with embedded Kubai icons, CSS, and the favicon to `dist/`. The browser transfer and motion modules in `dist/` are maintained directly, alongside the licensed fonts in `dist/fonts/`.
- Use semantic elements first. Name classes and section IDs in lowercase kebab case and keep IDs descriptive and unique. Prefer existing CSS custom properties and component classes for shared styling.
- Follow DRY, KISS, and YAGNI. Consolidate proven duplication when it clarifies the change. Keep a one-off component local until reuse justifies extraction. Introduce dependencies only when an approved feature needs them.
- Use direct, concise interface copy. Preserve exact approved product wording and keep example data clearly labeled.
- Write server code in strict TypeScript under `src/` and use `.js` extensions in relative ESM imports so they resolve in Node. Use the same import convention for build-time React components. Run the Node and Playwright checks in `tests/`. Keep `build/` out of source control and update `package-lock.json` when dependencies change.
- Lightswind registry files live in `frontend/lightswind/` and are sourced from revision `a3895bd6968b5d96425eb45edcc84a1d79b3ecb4`. The script-free SVGs in `frontend/icons/` were exported from Kubai revision `7459692178f673595de5192e988dc7f610e04026` using the soft variant with a blue accent (`#5375D9`). Keep [Lightswind](../licenses/Lightswind.txt) and [Kubai Icons](../licenses/Kubai-Icons.txt) notices with the project.
- Record upstream revisions and local adaptations in [FilePizza adaptations](filepizza.md). Keep the FilePizza license in source and deployment artifacts. Run signaling and real browser transfer tests when changing the PeerJS client or server version.
- Validate HTTP, WebSocket, and DataChannel inputs at the boundary. Handle errors where callers can act on them. Use stable error codes and short user-facing messages. Keep startup diagnostics generic and keep tokens, invite URLs, filenames, SDP, ICE, and personal data out of logs. See [api.md](api.md) and [security.md](security.md).
- Add environment settings to `readConfig` and `.env.example` together, with explicit defaults and bounds. Keep HTTP error responses in the shared `{ error }` format. Update [api.md](api.md) when an HTTP or WebSocket error code changes.
